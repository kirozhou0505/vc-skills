# 输出格式

## 修订稿

修订稿要完整呈现逐字稿，保持原有段落、说话人和时间戳。正文只放修订后的内容；修改处需要可见标记。

优先使用 HTML 颜色标记：

```html
这是<span style="color:#1565C0">修订后的文本</span>，其余内容保持原样。
```

如果需要同时展示被替换的旧词，可在同一处使用：

```html
<span style="color:#C62828;text-decoration:line-through">旧词</span>
<span style="color:#1565C0">新词</span>
```

在纯 Markdown 或聊天窗口中，使用以下降级格式（禁止方括号【】与各类双引号）：

```text
这是 ~~旧词~~ **新词** 后的句子。
```

中置信度的改动在改后文本后加（待确认）。低置信度项目不要把猜测塞进修订稿。

## 修改记录

优先用 Markdown 表格；原文或证据链接过长时，可以在表格后按编号补充。修改记录放在文档里，不要整表贴进聊天。

| # | 定位 | 原文 | 改后文本 | 类别 | 修改理由 | 核查依据 | 置信度 | 状态 |
|---|---|---|---|---|---|---|---|---|
| 1 | 发言人 A / 00:12:08 | 旧词 | 新词 | 专名 | 与官方名称一致 | 来源标题与链接，访问日期 | 高 | 已改 |

状态只使用：已改、已改但待确认、未改待确认。同一个位置有多个独立问题时拆成多条，避免一条记录混合不同证据。

## 核查摘要

用一两句话报告：直接修改数、待确认数、未完成外部核查数。不要把摘要写成新的会议纪要。聊天里只给要点，以及确实无法外部核实、必须用户拍板的极少数项。
