# 项目背景讲解

## 目标与读者
面向有投资经验、但未必熟悉目标行业的读者，补齐理解整份材料所必需的context。交付的不是会议纪要、公司名录、英文缩写词典或投资入门课程，而是一份沿项目逻辑展开的背景讲解：谁在做什么，产品如何工作，为什么会上会提到这些对象，以及它们如何影响对项目的理解。

## 默认学习顺序：小白入门 → 技术进阶 → 公司介绍
默认按以下三个阶段组织，分别交付三份Markdown文件。它们是同一条理解主线的递进，不是三篇互不相关的文章。用户明确只要其中一部分或指定其他格式时，以本次要求为准。

### 第一阶段：小白入门
- 假设读者没有该行业的技术基础。围绕理解本项目所必需的知识，不泛讲整个产业，不先堆公司名与英文缩写
- 先说最终做出的实物或服务是什么、谁用、用来完成什么任务，再从一个具体需求出发，把从起点到最终可用结果的完整流程串起来
- 每出现一个必要术语，先说明它对应的实物、动作或结果，再给名称，解释为什么需要这一步、上一步交给下一步什么
- 用一个完整案例贯穿，讲清中间产物与最终成品、不同设备或角色各自负责的部分。不能假定“设计”“制造”“验证”等词的工程含义读者已经理解
- 以自然段讲解，必要时用简短流程图。不是术语词典，也不是靠更多陌生词解释陌生词。类比只能辅助，随后回到真实对象和机制，不以失真的类比替代解释
- 最后让读者能用自己的话说明：行业在做什么、流程怎么走、本项目改变哪一步；不要求先掌握参数和复杂原理

### 第二阶段：技术进阶
- 沿用第一阶段的同一流程与案例，不另起一套叙述。只简短回顾必要背景，再补“具体怎么做到、为何不同方案效果不同”
- 解释关键物理或工程原理、材料与部件、工艺或算法、输入输出、关键指标及其实际影响
- 对主要技术路线讲清实现方式、适用场景、能力边界、另配条件与取舍，不只列有无功能或泛泛优缺点
- 明确哪些环节可由单一产品完成，哪些依赖其他软件、设备、材料或人工；区分实验演示、可稳定交付与量产能力
- 保留理解项目所需的技术细节，但不堆无关知识，不因“进阶”变回术语密集的材料复述

### 第三阶段：公司介绍
- 读者有了流程与技术基础后，再把材料中的公司放回产业位置：它负责哪一段、卖什么产品、客户如何使用、交付什么结果、如何赚钱
- 逐家解释关键竞品、供应商及其他相关对象，说明与本项目的关系、路线差异和比较边界；一般旁支的篇幅以解释会议语境为准
- 重要公司的详解可结合 company-deep-dive-explainer 技能，先加载再使用；不因此遗漏本技能要求的上下游、前司、渠道等关系
- 不把公司介绍写成一句话名片或产品清单，也不重复抄写前两篇技术科普。必要处引用已讲清的流程位置，集中解释公司的独特做法

三个阶段按顺序交付，不默认每一步都等待用户确认；可以先交付已完成的入门篇再继续后两篇。若用户说第一篇仍看不懂，回到具体实物与动作重讲，而不是增加更多术语。聊天只作简短说明，完整内容放文件；用户主动问具体问题时直接回答。

## 1. 完整读材料，内部建立覆盖清单
- 完整读取正文、附件及相关图表；区分正文与修改记录，修改记录仅帮助识别听写问题
- 提取所有相关中英文公司、品牌、产品、机构、渠道及必要技术、产品和行业概念，不只扫描英文名或只解释竞品
- 覆盖直接及间接竞品、替代方案、上下游供应商、代工厂、客户和渠道、创始团队前司与过往创业、被用来类比的公司及其他被投项目
- 每个对象记录会议语境、角色和必要时的时间戳，检查漏项；清单是内部核对工具，不要把一长张名称表当作最终解释
- 名称有歧义时结合上下文、官网与可靠资料核实。无法确认的保留原音或原文和不确定性，不凭谐音强认公司。公司、品牌、产品、技术、学校和平台应分清

## 2. 先建立理解项目的主线
先讲目标用户当前怎样完成任务、为什么现有方案不够好、项目准备改变哪一环。例如将防护、拍摄与通信的各类独立装备整合成一体，与单纯增加某个功能是不同路线。
按用户任务、产品运行过程或产业链组织解释，再把公司和术语嵌进去。不要机械照材料出现顺序逐个翻译，也不要让技术词互相解释形成循环。

## 3. 深入解释每家相关公司及其会议角色
对重要对象自然讲清：
- 它是谁、主要卖什么、卖给谁、靠哪类业务赚钱
- 代表产品如何使用，具体解决什么问题；用一个完整场景让读者看懂
- 为什么会上提它，它是竞争对手、供应商、渠道、履历线索还是类比对象
- 与项目相同及不同的地方，尤其是技术路线、客户任务、系统边界与商业模式，不写泛泛的功能列表
- 它的存在给项目带来什么实际约束或比较基准，例如兼容性、供应链依赖、用户迁移、渠道能力和替代方案
重要竞品、关键供应商充分展开；一般前司或旁支用足够解释会议语境的篇幅处理。不是所有提到的公司都是对手；前司业绩、供应商能力、其他被投项目的订单都不能记到本项目名下。

## 4. 解释必要技术、产品和行业术语
默认读者懂投资，缺的是行业和工程背景。基础投资、融资和财务术语不讲，如天使轮、估值、投前投后、毛利率、TAM/SAM/SOM等，除非用户主动问或材料中的特殊用法妨碍理解。
保留产品相关的成本结构、采购价格、物料清单、交付阶段、认证与渠道机制；解释其行业实际含义，而不是转成财务教学。必要时指出币种、分母或价格口径不明，不用长篇科普替代核对。
每个重要概念应让读者知道：
- 它在产品里起什么作用
- 通过什么机制工作，必要时拆到零件、信号或用户操作
- 一个完整的具体使用例子
- 它与相近概念的区别、失效条件或能力边界
- 为什么它会影响本次会议里的主张和方案取舍
可涉及材料所需的物理原理、制造工艺、传感器、算法、协议、能源、材料、认证、用户行为及销售渠道。不为显得全面而扩展无关知识。不要固定套用重复的五项小标题；以连贯讲解为主。

## 5. 核实并区分证据层级
- 一般技术事实、公司当前产品和公开数据优先查官网、标准机构、监管披露、公开财报及可靠一手资料；关键事实给来源链接
- 严格区分已公开验证事实、创始人或会议参与者自述、分析判断、用于说明机制的假设例子
- 合作、客户、授权、兼容、产品进度、效果提升和订单，未有独立证据就保持材料自述口径，不写成已验证结论
- 历史印象不能覆盖现有产品；对比竞品前核查当前产品线，不拿过时缺点当壁垒
- 安全结构或实验指标的改善不等于人体伤害概率同比改善；标准认证不等于覆盖所有事故
- 同一通用技术名不证明不同品牌协议兼容；有通信链路不证明所有联网服务可用
- 参与人数、人次、存量、年销量、部件行业估计与供应商自身出货不可混用；需要解释这些行业口径，但不展开投资术语基础课
- 查不到就说明未找到公开信息，不编造数据、人名、合作或名称对应关系；类比与示例明确标为示例

## 6. 输出与交付
- 默认中文，保留必要英文原名。默认按“小白入门、技术进阶、公司介绍”分别交付三份Markdown，文件顺序清楚；用户只要单篇时不强行扩成三篇
- 每篇先用几句话说清本篇主线，再按产业关系或产品运行链分组讲解；具体叙述深度按上述阶段区分
- 深度以读者能重新读懂材料为准：不要将公司压成一句话名片，也不要将术语压成中英对照表
- 解释公司与解释技术互相连接，不让同一内容反复出现；已有公司详解时，在新讲解中补必要关系而非全文重抄
- 将关键取舍串起来，如整合与可维修、性能与功耗、减重与防护、拍摄与安全感知、私有协议与用户迁移
- 来源放相应段后或集中于文末，避免每句话堆引用、破坏阅读。提供足够定位原材料的线索，但不机械附所有时间戳
- 未确认名称集中简列，不让不确定对象抢占主线
- 遵守本次用户指定的文档格式与当前环境的交付规则；聊天不铺文件全文
- 不要为凑完整度让用户一直等待。优先交付最影响理解的部分，再补齐其他部分；进度通知不能替代结果

## 7. 交付前自查
- 第一篇是否真能让没有行业技术背景的人理解实物、动作、完整流程和项目位置，而非只是把进阶篇删短
- 第二篇是否沿同一流程补足技术机制、指标和路线差异，而非重复第一篇或突然堆术语
- 第三篇是否把公司放回已经建立的行业流程，解释产品怎样工作及与项目的关系
- 公司是否覆盖中英文、上下游、竞品、前司和渠道，而不仅是知名英文品牌
- 技术概念是否真正解释了机制与例子，而非用更多术语替代解释
- 是否说明这些对象为什么出现在这次会议中，以及与项目的关系
- 是否误把访谈主张当事实、行业数量当公司销量、产品路线当已有能力
- 是否给投资从业者写了不必要的投资常识，或加入无关背景；有则删去
- 是否把内容组织成能理解项目的一条逻辑，而不是互不相干的词条合集
